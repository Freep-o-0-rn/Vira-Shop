# Адаптер Ozon ПВЗ — контракт интеграции (без ключей в репозитории)

**Текущий статус:** API и геокодирование не подключены. Нет доверенных координат
покупателя и списка действующих ПВЗ; поэтому UI не выбирает фиктивный пункт,
а `GET /api/account/checkout/pickup-points` отвечает HTTP 503.

## План подключения
1. Определить доступ к актуальному сервису Ozon Доставки для бизнеса и подтвердить
   условия его использования, лимиты, тарификацию, вид поддерживаемых отправлений.
   Не путать с обычным оформлением розничного заказа через Ozon.
2. Реализовать серверный адаптер по официальному контракту: авторизация хранится в
   переменных окружения, ответы валидируются, ошибки и недоступные ПВЗ отфильтровываются.
3. Геокодировать адрес покупателя с его согласия либо предоставить выбор на карте
   с явным подтверждением точки. Без подтверждённых координат не объявлять ПВЗ «ближайшим».
4. Полученные ПВЗ нормализовать в `DeliveryPoint` из `lib/logistics.ts`;
   алгоритм `recommendPickupPoint` сортирует по географическому расстоянию.
   Учитывать не только близость, но и поддержку габаритов, режима получения,
   актуальную доступность и тариф отправления.
5. На checkout предлагать рекомендуемую точку и возможность выбрать другую.
   При создании заказа **на сервере повторно проверить ID** через провайдера
   и сохранить в `shop_orders.delivery_point` снимок ID и адреса.
   Клиент не должен присылать произвольные адреса как доверенный ПВЗ.
6. Отдельно принимать подписанные или проверяемые сообщения о перемещениях
   отправления, применять идемпотентно к `shop_logistics_events` и изменять
   заказ только после подтверждения события.
7. Проверить сценарии: ПВЗ закрыт, нет точек в городе, устаревший список,
   смена пункта, сбой API, повторные webhook, ошибочная геопозиция и
   несоответствие данных адреса перед сохранением заказа.

До выполнения этих шагов выбор «ПВЗ Ozon» заблокирован. Оплата отдельно и не включена.
