# План развития Vira Shop

Обновлено: октябрь 2026. Целевая архитектура: сначала магазин **одного продавца**, позже — маркетплейс с несколькими продавцами.
План — рабочий, а не обещание сроков. Приоритеты уточняются после тестов каждой версии.

## Что уже реализовано (0.1–0.11)
- Next.js/React/TypeScript, мобильная витрина, категории, поиск, фильтры и карточки товаров.
- Локальная PGlite в папке `data/`, автоматические миграции, создание администратора, резервный перенос между папками.
- Административная панель товаров/категорий/заказов; фотографии в `public/uploads/`, характеристики, автоматические артикулы.
- Покупательские аккаунты, адреса, корзина и **заявки без оплаты** с проверкой наличия и отменой с возвратом остатков.
- Комбинации вариантов с отдельными SKU, ценами, остатками, изображениями и сохранением выбора в заказе.
- Проверки CI: TypeScript, Next.js, интеграционные тесты PGlite и Windows.

**Важно:** это функциональный MVP, но пока не готовый к публичным платежам/нагрузкам интернет-магазин.
Демо-цены, товары и отзывы не являются настоящим коммерческим предложением.

## Vira Shop 0.12 — UX вариаций (реализовано)
- Быстрые шаблоны групп «Цвет / Размер / Длина / Комплектация».
- Массовое редактирование **выделенных** комбинаций (цена, остаток, показать/скрыть), поиск по комбинациям.
- Предупреждение о несохранённых изменениях; редактирование старой цены.
- Витрина явно показывает распроданные или несовместимые варианты, не допускает несуществующие комбинации.
- Ссылка на конкретный вариант (`?sku=числовой_артикул`) для копирования и повторного открытия.
- Тесты сопоставления опций и совместимости.

## Vira Shop 0.13 — каталог и учёт товаров (реализовано)
- Реализовано: копирование карточек и действующих комбинаций с новыми артикулами, новая копия скрыта, остатки сброшены.
- Реализовано: поиск по SKU вариантов, фильтры остатков, массовая установка цены/остатка/видимости одной транзакцией.
- Реализовано: массовая цена/остаток не меняют товары с вариациями, их редактируют отдельно.
- Следующим отдельным этапом: **журнал складских движений** (включая поступления и возвраты), шаблоны атрибутов, безопасная очистка неиспользуемых фотографий.

## Vira Shop 0.14 — оформление заказа (реализовано)
- Реализовано: самовывоз с контактом без адреса, доставка по сохранённому адресу, предварительный серверный расчёт цен/остатков, снимок выбранного способа получения в заказе.
- Реализовано: стоимость самовывоза 0 ₽, неизвестная стоимость доставки хранится как NULL и ясно обозначена покупателю. Оплата не подключена, платежи не создаются.
- Совместимость: ранее созданные заказы сохранены; создание старой заявки без нового поля остаётся доставкой по адресу.
- Дальше: настройка реальных точек самовывоза, тарифов и сроков доставки по выбранной зоне, контактное подтверждение.
- Полная интеграция гостевой/авторизованной корзины и согласование устаревших остатков остаются задачами дальнейшей UX-доработки.

## Vira Shop 0.15 — заказы и работа продавца (реализовано)
- Реализовано: серверный поиск и фильтры статусов с постраничной загрузкой, отдельная карточка и подробный журнал обработки.
- Реализовано: создание/переход статуса записываются транзакционно, прошлые переходы старых заказов не реконструируются.
- Реализовано: защита от повторного возврата остатков при отмене, тест одновременных административных запросов.
- Дальше: безопасная политика времени резерва, журнал складских движений, уведомления и печатная карточка сборки.
- Взаимодействие с реальной оплатой и подтверждением доставки — отдельные будущие интеграции.

## Vira Shop 0.15.1 — логистика и автоматизация (текущая версия)
- Реализовано: независимый статус выполнения заказа, журнал событий,
  внутренний источник товара, перевозчик, трек-номер и защищённая ссылка закупки.
- Реализовано: безопасные автоматические переходы после подтверждения продавцом,
  передачи перевозчику, вручения и отмены; без фиктивных событий по таймеру.
- Реализовано: ручная транспортная компания, индикатор ожидания новых заказов.
- Основа ПВЗ Ozon: модель проверенной точки и поиск ближайшей по координатам;
  **реальный API и карта выбора пока не подключены**, выбор ПВЗ закрыт.
- Дальше: доступ к официальному API, геокодирование, подтверждённые ПВЗ,
  интеграция доставки и уведомлений, очередь фоновых задач с защитой дублей.

## Vira Shop 0.16 — инфраструктура и сохранность данных
- Отказ от локальной PGlite в production в пользу управляемой PostgreSQL.
- Миграция данных без потери артикулов, покупателей, заказов и связей вариантов.
- Объектное хранилище фото, Docker/VPS, домен, HTTPS, ограничение запросов и мониторинг.
- Автоматические шифрованные резервные копии + **проверка восстановления**, план возврата предыдущей версии.
- Раздельные среды разработки, тестов и производства; секреты вне репозитория.

## Vira Shop 0.17 — платежи и юридическая готовность
- Выбор платёжного провайдера и схемы оплаты после решения по стране и юридическому лицу.
- Заказы: резерв, создание платежа, серверные webhooks с подписью/идемпотентностью, возвраты.
- Тесты повторных уведомлений, отказов, неполной оплаты и изменения цены.
- Требуемые документы/чеки/политики конфиденциальности и возвратов.

## Vira Shop 0.18 — выпускной аудит
- Авторизация/разграничение доступа, CSRF/XSS/SQLi, rate limiting, защита файловой загрузки.
- Регрессионные E2E-тесты: разные артикулы в одной корзине, конкурирующие заказы, восстановление бэкапа.
- Производительность мобильной версии, доступность, SEO, реальные фото и контент.
- Пробный запуск без онлайн-оплаты, устранение ошибок перед публичным запуском.

## 1.0 — первый публичный магазин
Только после успешной проверки доставки, заказов, оплаты, бэкапов и юридических требований.

## После 1.0 — маркетплейс, если действительно понадобится
Несколько продавцов потребуют самостоятельной модели владельцев товаров, комиссий, выплат, модерации, возвратов и разрешений.
Не смешивать это с первой версией одного продавца.

## Правила разработки
1. Сохранять ID и SKU; не удалять каскадно данные о старых заказах.
2. Любые изменения резервирования — только в транзакциях с тестами на двойное списание.
3. Каждая версия: `npm run typecheck`, `npm run build`, тесты API/PGlite и Windows-переноса.
4. Обновление привычным способом: скачать ZIP в **новую папку** → `IMPORT-DATA-WINDOWS.bat` → `START-WINDOWS.bat`.
5. Перед каждой миграцией production создавать резервную копию и проверять её восстановимость.
