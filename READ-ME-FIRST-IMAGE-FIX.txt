УСТАНОВКА (Windows, локальный сервер):
1) Остановите Next.js. Для резервной копии/переноса БД обязательно остановите все процессы, использующие PGlite. Caddy тоже можно закрыть.
2) Переименуйте текущую C:\_BOTS\Vira-Shop-main в C:\_BOTS\Vira-Shop-main-BROKEN.
   Не удаляйте эту папку: в ней база data\ и пользовательские public\uploads\.
3) Распакуйте ЭТОТ ZIP в C:\_BOTS\. Должна получиться НОВАЯ папка C:\_BOTS\Vira-Shop-main.
   Не оставляйте вложенного C:\_BOTS\Vira-Shop-main\Vira-Shop-main.
4) Перенесите из старой папки в новую конфигурацию .env / .env.local (если она есть)
   и пользовательский BAT запуска, если он находится внутри проекта. Caddyfile в C:\Caddy не трогайте.
5) Запустите в новой папке IMPORT-DATA-WINDOWS.bat. Когда скрипт спросит путь к ПРЕЖНЕЙ версии,
   введите C:\_BOTS\Vira-Shop-main-BROKEN. Он переносит data\ и public\uploads\.
   Не запускайте SETUP-DATABASE-WINDOWS на старой базе перед импортом.
6) В PowerShell:
   cd C:\_BOTS\Vira-Shop-main
   npm.cmd install --no-audit --no-fund
   npm.cmd run build
   npm.cmd run start -- -H 127.0.0.1 -p 3000
   Окно Next.js оставьте открытым.
7) Проверьте в браузере http://127.0.0.1:3000/ и http://127.0.0.1:3000/catalog.
   Оба адреса должны открываться. Только после проверки запускайте обычный единый BAT/Caddy.
8) Убедитесь, что в .env.local для публичного адреса задано APP_ORIGIN=https://v54.shop.
   Если производство использует загрузки файлов, задайте VIRA_LOCAL_UPLOADS=1 и делайте резервные копии.

Проверка демонстрационных фото:
  http://127.0.0.1:3000/api/demo-image/photo-1505740420928-5e560c06d30e
При первом обращении сервер должен скачать изображение и сохранит в public/uploads/demo-photo-cache.
Если увидите HTTP 502, сервер не смог связаться с удалённым фотосервисом; это отдельная
проблема доступности изображений, а НЕ повод заново заменять сайт.
