# Vira Shop 0.7 — страницы каталога и ссылки на фильтры

В версии 0.7 появились постоянные адреса для основных разделов:

- `/catalog` — каталог с фильтрами, которые записываются в URL.
- `/favorites` — избранное.
- `/cart` — корзина.
- `/product/ID` — отдельная карточка товара.

Например, `/catalog?category=electronics&sort=cheap&minPrice=1000&maxPrice=10000&inStock=true&page=2` откроет вторую страницу электронных товаров в ценовом диапазоне от 1000 до 10000 рублей по возрастанию цены, только в наличии.

Поиск применяется при нажатии «Найти», цену нужно подтвердить кнопкой «Применить цену». Категория, сортировка, наличие и пагинация обновляют адрес сразу. Кнопки браузера «Назад/Вперёд» восстанавливают выбранные фильтры. Ссылки на карточки теперь доступны через обычное открытие в новой вкладке.

**Как обновиться:** скачайте ZIP ветки main в новую папку. До запуска нового сайта закройте старый и запустите `IMPORT-DATA-WINDOWS.bat` из новой папки, указав старую версию. После успешного переноса `START-WINDOWS.bat` применит миграции. Старая папка остаётся нетронутой, `data/` и `public/uploads/` не публикуются в GitHub.

Версия предназначена для локального тестирования; онлайн-оплата не подключена.

## Vira Shop 0.6 — перенос данных и резервные копии

**Подходит для твоего способа обновления: каждая новая версия в отдельной папке.**

1. Останови оба сервера Vira Shop (Ctrl+C), включая старую версию.
2. Распакуй свежий ZIP GitHub **в новую папку**, но пока не запускай `START-WINDOWS.bat`.
3. В **новой** папке запусти **`IMPORT-DATA-WINDOWS.bat`**.
4. Введи полный путь к папке старой версии, например `E:\Work\Vira-Shop-0.5.2`.
5. Скрипт скопирует `data/` (PGlite PostgreSQL, аккаунты, каталог, заказы) и `public/uploads/` (фотографии), не изменяя старую папку.
6. Теперь запускай `START-WINDOWS.bat` **из новой** папки. Миграции применятся автоматически.

Если в новой папке уже есть данные, перенос запросит точную команду **REPLACE** и сначала переместит существующие данные в `backups/pre-import-...`. Ничего не удаляется без явного подтверждения. Если перенос не завершился, НЕ запускай магазин, пока не проверишь сообщения скрипта и резервную копию.

**`BACKUP-DATA-WINDOWS.bat`** в текущей папке создаёт резервную копию базы и фотографий в `backups/manual-...`. Перед копированием останови сервер. Не редактируй файлы внутри `data/pgdata/` вручную.

**Защита от ошибок:** запускатор не разрешает два сервера из одной папки и останавливает запуск, если порт 3000 занят. Новые версии используют файл блокировки `.vira-running.lock`; при переносе из старых версий, где его ещё не было, дополнительно проверяются работающие процессы Node.js. Всё равно необходимо вручную закрыть оба окна перед переносом.

Пока это **локальный помощник переноса**, а не автоматическое скачивание релизов. ZIP по-прежнему скачивается вручную. В будущих версиях можно добавить проверку обновлений с GitHub.

**Важно:** папки `data/`, `public/uploads/` и `backups/` не отправляются на GitHub. Не удаляй старую папку до проверки входа администратора и наличия товаров в новой. Храни копии также вне диска с магазином.

## Учётные записи и пароли

- Пароль **покупателя** при регистрации: минимум **6 символов**. Ограничение проверяется и в форме, и в API. Это упрощение только для локальных тестов; для публичного магазина следует ввести более строгую политику паролей и защиту от перебора.
- **Администратор** входит на `http://localhost:3000/admin/login` по **логину**, не по email. Пароль администратора по-прежнему должен содержать **не менее 12 символов**.
- Чтобы **сбросить пароль администратора**, остановите сайт (Ctrl+C), затем запустите `CREATE-ADMIN-WINDOWS.bat` **в той же папке проекта, где лежит база `data/pgdata/`**. Введите прежний логин, например `oksi`, новый пароль и его подтверждение. Символы пароля **видны при вводе**. Список существующих логинов будет показан перед запросом. Скрипт изменяет пароль без удаления товаров и заказов.
- Скрипт выводит полный путь к используемой базе; если на компьютере несколько папок Vira Shop, убедитесь, что запускаете нужную. Не отправляйте скриншоты с открытым паролем и не запускайте скрипт на чужом компьютере.

## Локальная база



В этой версии **Vira Shop работает без Docker и без установленного PostgreSQL**.

Используется **PGlite** — локальная встраиваемая PostgreSQL. Она хранит данные в каталоге `data/pgdata/` прямо внутри папки проекта. Важно: это **не одиночный файл SQLite**, а каталог с файлами PostgreSQL. Для этого проекта такой формат позволяет сохранить действующие запросы, миграции и транзакции заказов.

## Запуск

1. Установите Node.js LTS (22 или новее).
2. Скачайте архив [Vira-Shop](https://github.com/Freep-o-0-rn/Vira-Shop) → **Code → Download ZIP** и распакуйте в новую папку, например `D:\Vira-Shop-0.5.1`.
3. Запустите **`START-WINDOWS.bat`**. На первом запуске он установит зависимости, создаст каталог `data/pgdata/`, применит миграции и добавит 12 демонстрационных товаров.
4. Откройте `http://localhost:3000`. Если порт занят, используйте адрес, напечатанный в консоли.
5. Администратора создайте с помощью **`CREATE-ADMIN-WINDOWS.bat`**, предварительно закрыв сайт (Ctrl+C), чтобы база не была открыта другим процессом.
6. Запустите сайт снова. Панель: `http://localhost:3000/admin/login`.

`SETUP-DATABASE-WINDOWS.bat` теперь просто создаёт/обновляет локальную БД и **не требует Docker**. В норме его запускать не обязательно: всё уже делает `START-WINDOWS.bat`.

## Когда вы скачиваете каждую версию в новую папку

Для примера:
```text
D:\Shop\Vira-Shop-0.5.1\
  START-WINDOWS.bat
  data\
    pgdata\    ← ВСЕ данные: администраторы, товары, заказы
```

**Следующая новая папка не наследует базу автоматически**: это будет отдельная свежая база, пока не появится обновлятор.

Чтобы перенести существующую БД в следующую папку **без потери информации**:
1. Полностью закройте сайт в старой папке (`Ctrl+C`). Не запускайте две версии параллельно с одной базой.
2. Скопируйте папку `data` **целиком** из старой версии в новую, до запуска нового сайта.
3. Запустите `START-WINDOWS.bat` в новой версии: миграции применятся поверх скопированных данных.

**Не переносите отдельные файлы внутри `pgdata`!** Копируйте папку целиком и только когда сервер остановлен. Архивировать или копировать её во время работы сайта нельзя без механизма согласованного резервного копирования.

`data/` добавлена в `.gitignore` и не отправляется на GitHub. Будущий обновлятор должен сохранять `data/` и `public/uploads/` без перезаписи. Текущее поведение специально оставлено таким, чтобы вы могли по-прежнему скачивать ZIP в новые папки.

## Что сохранено

Каталог, категории, поиск, фильтры, страницы товаров, галереи, кабинет покупателя, адреса, серверная корзина, создание заказов в транзакции и административная панель с управлением заказами.

Онлайн-оплата отключена. Это демонстрационный MVP, не готовый для публичных продаж. Для реального магазина понадобятся отдельная промышленная PostgreSQL, резервные копии, антибот-защита, верификация email, HTTPS и защита персональных данных.

## Если раньше вы уже использовали Docker PostgreSQL

Локальная база PGlite не импортирует содержимое старого PostgreSQL автоматически. Если в Docker есть важные данные, **не удаляйте его том** — потребуется отдельный экспорт и импорт. Если ранее база вообще не создалась, ничего переносить не нужно.

## Проверка

`npm run db:seed` — создать/обновить локальную базу, не затирая существующие товары.
`npm run db:setup` — применить миграции.
`npm run admin:create` — создать/сбросить администратора, сайт должен быть остановлен.
`npm run typecheck` и `npm run build` — проверки исходного кода.

GitHub Actions тестирует PostgreSQL SQL на PGlite без Docker, а также авторизацию покупателей, управление заказами и Windows-запускатор.
