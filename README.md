# Vira Shop

**Версия 0.2 — основа интернет-магазина на Next.js, TypeScript и PostgreSQL.**

Сейчас доступны: адаптивная главная страница, каталог, категории, поиск и сортировка, карточки товаров, избранное, корзина (localStorage), API товаров и категорий, SQL-миграции и тестовые данные.

**Это прототип, а не готовый магазин:** реальные заказы, оплаты, покупательские аккаунты, редактирование товаров и доставка пока не реализованы. Демонстрационные цены, отзывы и остатки вымышлены.

## 1. Быстрый запуск сайта на Windows — без базы данных

1. Установите [Node.js LTS](https://nodejs.org/) **22 или новее**.
2. Скачайте репозиторий (**Code → Download ZIP**) и распакуйте, например в `E:\Work\Vira-Shop`.
3. Запустите `START-WINDOWS.bat`. При изменении `package.json` запускатор обновит npm-зависимости сам.
4. Откройте адрес, показанный консолью, обычно `http://localhost:3000`.

В таком режиме серверное API отдаёт **демонстрационные данные из кода**. Сайт и корзина работают, PostgreSQL не требуется. При необходимости проверьте `http://localhost:3000/api/products` и `http://localhost:3000/api/categories` (в JSON поле `source` будет `demo`).

## 2. Подключаем локальную PostgreSQL

Нужен установленный и **запущенный** [Docker Desktop](https://www.docker.com/products/docker-desktop/) (в Windows обычно используется WSL 2). Docker не требуется для этапа 1.

Самый короткий способ:

1. Закройте работающий сервер Vira Shop (`Ctrl+C` в окне).
2. Запустите **`SETUP-DATABASE-WINDOWS.bat`** из корня проекта.
3. Скрипт создаст `.env.local` (если его нет), поднимет локальную PostgreSQL через `docker compose up -d --wait db`, применит миграции и добавит 12 учебных товаров.
4. Запустите `START-WINDOWS.bat` заново. Откройте `http://localhost:3000/api/products`: поле `source` должно быть `database`.

**Важно:** если вы уже создали `.env.local`, скрипт не перезаписывает его. Сверьте `DATABASE_URL` с настройками в `compose.yaml`. Если порт 5432 занят другой базой, потребуется изменить проброс в Compose и адрес в `.env.local`. Логи запуска сайта: `vira-startup.log`; настройки БД: `vira-database-setup.log`.

Вручную из терминала:

```powershell
copy .env.example .env.local
docker compose up -d --wait db
npm install
npm run db:seed
npm run dev
```

Если Docker Desktop не запускается, можно использовать установленную вручную PostgreSQL — достаточно задать корректный `DATABASE_URL` в `.env.local` и выполнить `npm run db:seed`.

### Команды базы данных

- `npm run db:setup`: применяет все новые SQL-миграции, не заполняет товары.
- `npm run db:seed`: применяет миграции и добавляет демонстрационные категории и товары, **не переписывая уже существующие записи**.
- `docker compose stop db`: останавливает локальную PostgreSQL, сохраняя данные на диске.
- `docker compose up -d db`: запускает ранее созданную PostgreSQL с сохранёнными данными.

**Не выполняйте** `docker compose down -v`, если хотите сохранить данные: `-v` удаляет том базы.

### Как устроены данные

- `shop_categories`: категории магазина, название, иконка, порядок.
- `shop_products`: товары, категория, цены, наличие, изображения, рейтинг, признак активности.
- `shop_schema_migrations`: журнал применённых миграций.
- Цены хранятся целыми копейками в `price_minor` — без ошибок десятичной арифметики в PostgreSQL.
- API пока **только на чтение**, без редактирования через публичные маршруты.

### API

- `GET /api/products`: товары; параметры `q`, `category`, `sort=popular|cheap|expensive|rating`, `page` (от 1), `limit` (1–100). Возвращает `items`, `total`, `page`, `limit`, `source`.
- `GET /api/categories`: категории и `source`.

Например `/api/products?q=наушники&category=electronics&sort=cheap&limit=12`. Поиск и сортировка поддерживаются в PostgreSQL; SQL-запросы параметризованы. На главной странице пока отображается первая сотня товаров; полноценная навигация по страницам каталога появится в следующем этапе.

Если `DATABASE_URL` не задан, API использует демонстрационный набор. Если `DATABASE_URL` задан, но PostgreSQL не отвечает, API возвращает **503**, а браузер явно предупреждает, что отображает запасные демо-товары. Подмена данных не происходит незаметно.

## 3. Проверки

```powershell
npm run typecheck
npm run build
```

GitHub Actions автоматически выполняет проверку TypeScript и сборку проекта без БД, отдельную интеграционную проверку API с PostgreSQL и проверку Windows-скрипта.

## 4. Следующие этапы

1. **Сейчас:** локальный каталог и PostgreSQL, тестирование API и соединения.
2. Управление товарами и категориями через защищённую административную панель (авторизация, загрузка изображений, остатки).
3. Пользователи, адреса, настоящая серверная корзина и оформление заказов с транзакциями и проверкой цены/наличия на сервере.
4. Оплата и доставка — после выбора страны работы, платёжного провайдера и договорных условий.
5. Подготовка к публичному запуску: VPS, HTTPS, домен, секреты, бэкапы и мониторинг.

## Безопасность

Локальные реквизиты в `compose.yaml` предназначены **только для разработки**. PostgreSQL слушает исключительно `127.0.0.1:5432`; не используйте эти пароли на публичном сервере. `.env.local` исключён из Git, не публикуйте настоящие ключи. Фотографии Unsplash — временные изображения; перед запуском замените их собственными или лицензированными.

**Важно:** корзина в браузере не является доверенным источником стоимости заказа; суммы и остатки необходимо проверять на сервере перед приёмом оплаты.
