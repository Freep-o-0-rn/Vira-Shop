# Vira Shop — версия 0.5

Учебный MVP интернет-магазина (Next.js, TypeScript, PostgreSQL): каталог, фильтры, карточки с галереями, администрация, аккаунты покупателей, адреса и **заявки на заказы без онлайн-оплаты**.

## Обновление на Windows

1. Скачайте ветку main: **Code → Download ZIP**, распакуйте в новую папку.
2. Если PostgreSQL уже содержит данные, **рекомендуется обновлять файлы в прежней папке проекта**, сохранив `.env.local` и данные Docker. Docker Compose использует имя папки для определения проекта; распаковка в другую папку может создать *новую пустую базу* вместо прежней. Если перенесли проект, сначала проверьте `docker compose ls` и название исходного проекта/тома. Не удаляйте Docker-том базы.
3. Запустите Docker Desktop, затем `SETUP-DATABASE-WINDOWS.bat`. Миграции 004 и 005 добавят таблицы покупателей, корзин и заказов; существующие карточки товаров сохранятся.
4. Если администратор ещё не создан: `CREATE-ADMIN-WINDOWS.bat`.
5. Запустите `START-WINDOWS.bat` и откройте адрес, который он покажет (обычно `http://localhost:3000`).

**Важно:** если при распаковке переместили проект в другую папку, `.env.local` не переносится автоматически. Если база уже содержит ваши изменения, не запускайте `docker compose down -v` — эта команда удаляет том с данными.

Без PostgreSQL остаётся доступной демонстрационная витрина. Регистрация, оформление заявок и панель администратора требуют настроенной PostgreSQL.

## Что нового

- `/account` — регистрация по email и паролю (от 12 символов), вход, сохранённые адреса, история заказов и выход.
- `/checkout` — серверная корзина: при первом открытии после входа переносит товары из локальной корзины; можно менять количество. Заявка оформляется только при выбранном сохранённом адресе.
- После оформления сайт показывает номер заявки, товары резервируются в БД и удаляются из серверной корзины.
- `/admin` → **Заказы** — просмотр заявок, ФИО, адреса, перечня товаров, суммы, смена статуса. Отмена до отправки возвращает товары на склад.
- Сервер проверяет актуальные цены, видимость товаров и достаточность остатков. Создание заказа идемпотентно по ключу запроса.
- Заказ хранит **снимок цен и адреса**: последующее изменение каталога или удаление сохранённого адреса не искажает историю.

### API

Покупатель (HttpOnly cookie):
- `POST /api/account/register` — регистрация.
- `GET/POST/DELETE /api/account/session` — профиль, вход, выход.
- `GET/POST/DELETE /api/account/addresses` — адреса.
- `GET/POST/PUT /api/account/cart` — чтение, перенос/слияние локальной корзины, установка количества.
- `GET/POST /api/account/orders` — история, создание заявки.

Администратор:
- `GET /api/admin/orders` — последние 100 заказов.
- `PATCH /api/admin/orders/:id` — разрешённые переходы статусов:
  `new → confirmed → packing → shipped → completed`. До отправки можно отменить заявку; остатки восстанавливаются один раз.

Маршруты каталога и админ-панели версии 0.4 сохранены.

## Границы безопасности и коммерческой готовности

Это **не готовый публичный магазин**. Пароли хешируются (scrypt), сессии HttpOnly, изменение данных проверяет Origin, неудачные попытки входа временно блокируются. Но **нет подтверждения email, восстановления пароля, защиты регистрации от массовых запросов, антибот-защиты, юридических документов и проверки персональных данных для публичной эксплуатации**. Для приёма реальных клиентов необходимо внедрить эти механизмы и соблюсти применимые требования защиты персональных данных.

- **Онлайн-оплата полностью отключена.** `payment_status=unpaid`; сайт не собирает платежные реквизиты и не выставляет счета. Статусы — тестовая операционная модель.
- Сумма заказа включает товары, но **не доставку**. Нет расчёта тарифов, интеграции служб доставки и резервирования с истечением срока. Не рассматривайте демонстрационные товары как реальные предложения.
- Корзина витрины до оформления остаётся в браузере. При открытии `/checkout` покупатель синхронизирует её с сервером. На другом устройстве серверная корзина видна на `/checkout`.
- Если заказ успешно создан, но ответ сервера потерялся, повтор того же запроса с тем же UUID возвращает исходный заказ, предотвращая двойное списание остатков.
- Для публичного развертывания задайте `APP_ORIGIN=https://ваш-домен` и HTTPS, замените разработческие пароли, настройте аудит, резервные копии и отдельное хранилище фотографий.
- Личные адреса и email следует хранить и обрабатывать в соответствии с законодательством страны продаж; до запуска публичного сервиса эти вопросы не решены.

## Проверка и диагностика

`npm run db:setup` — миграции; `npm run db:seed` — демотовары без перезаписи существующих; `npm run admin:create` — создать/сбросить администратора. `npm run typecheck`, `npm run build` — проверки кода.

GitHub Actions запускает сборку без базы и интеграционные тесты PostgreSQL, включая регистрацию покупателя, передачу корзины, создание заказа, повтор запроса, проверку остатков, отмену и статусы. Журналы запуска: `vira-startup.log`, `vira-database-setup.log`.
